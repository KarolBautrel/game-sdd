# Character art tooling acceptance

Owner: [tooling005](../005_character_art_pipeline.md).

1. Inspect the existing eight-direction renderer and installed skills/services;
   choose tools compatible with the existing engine and approved visual style.
2. Pin downloaded tools, source commits and licence evidence. Install focused
   missing skills without replacing existing ones.
3. In background Blender, create an isolated diagnostic scene, save .blend,
   render PNG, export FBX, re-import FBX and report mesh/rig/animation evidence.
4. Initialize the selected MCP server, enumerate tools and execute a local scene
   query/edit against the isolated diagnostic scene. Record any reconnect or
   headless-vs-interactive limitations explicitly.
5. Download only a free animation-library edition; import the downloaded file and
   report real clip counts, skeleton information and licence.
6. Document optional PixelLab/Meshy account/API prerequisites, costs and rigging
   limits from current primary sources. Do not spend credits or claim connection.
7. Persist the research, installed paths, reproduction commands and next pilot
   acceptance checklist. Existing gameplay/UI acceptance remains deferred until
   the user releases physical controls.

Proof: the tooling setup report and ignored machine-readable smoke artifacts
linked from docs/design/character-art/TOOLING.md. These are toolchain checks,
not normal gameplay or approval of a production character's appearance.
