# Development tooling

Tooling owns local setup, validation orchestration, diagnostic evidence and
interactive QA launch. Gameplay rules remain in the combat and dungeon domains.

- `001_stage_verification.md`: commands, evidence and stage gates.
- `slices/001_environment_baseline.md`: acceptance scenarios for stage 0.
- `002_exportable_asset_catalogue.md`: imported textures, deterministic catalogue and Windows export.
- `slices/002_exportable_asset_catalogue.md`: acceptance scenarios for stage 2.
- `003_map_authoring_v2.md` and `slices/003_map_authoring_v2.md`: Tiled metadata and playable workbench.
- `004_final_acceptance.md` and `slices/004_final_acceptance.md`: integrated release regression.

Stage results are recorded in `docs/qa/stages/`. Raw logs and machine reports live
in ignored `artifacts/qa-runs/`.
